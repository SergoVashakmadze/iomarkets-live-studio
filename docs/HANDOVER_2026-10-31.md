## Rules learned the hard way

1. **Never deploy while someone is in an interview.** The web app runs one container. A deploy
   moves new requests to a new container that does not know the running interview, and its
   answer uploads return 404. Three answers of the operator's Oct 31 interview were lost this
   way. Check first; this prints nothing when the studio is quiet:
   ```sh
   uv run --no-project --with modal==1.6.1 modal app logs iomarkets-live-studio --since 5m \
     --timestamps | grep -E "/media/|/api/answers|CONNECT /ws|/api/brief"
   ```
   On Monday, when testers may be live at any hour, do not deploy unless something is broken.
2. **A secret change needs new containers.** `modal deploy` skips the deploy when the code is
   unchanged, and running containers keep the old secret. Make a real code change, or stop the
   web container from the Modal dashboard.
3. **Do not re-run `deploy/deploy.sh` this week.** It rotates `STUDIO_TOKEN`, which would break
   the link all five testers have. To change the secret, rebuild it from `.env` with the same
   token (META_API_KEY, FIREWORKS_API_KEY, STUDIO_TOKEN from the link file,
   STUDIO_DAILY_BUDGET_USD), as done on Oct 31.
4. **Pictures carry a fingerprint in their URL**, so a changed anchor shows at once. Before this,
   browsers cached the old one for an hour.

## Running it locally

```sh
uv run studio serve                                   # http://127.0.0.1:8000, MMS voice only
# the native voice (Python 3.10 env, already built in ~/.cache/iomarkets-voice):
~/.cache/iomarkets-voice/bin/python voice/server.py   # :8767
STUDIO_TTS_URL=http://127.0.0.1:8767 uv run studio serve
```
Rebuild the voice env if it is missing: see the docstring of `voice/server.py`.
