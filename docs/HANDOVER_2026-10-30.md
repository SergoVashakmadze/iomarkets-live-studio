## What works now

- **The studio page** is a broadcast control room: logo, ON AIR tally, a two-box programme (the
  AI anchor and the guest side by side in the IoMarkets TV studio), name straps, ticker, and a
  programme recording that downloads as WebM at the end.
- **The anchor**, "Alexandra Morgan" (Teresa, a pre-existing HeyGen avatar), lip-synced with head
  and body movement by `lipsync/server.py` (MuseTalk v1.5 over her moving loop). Her voice is
  en-GB-LibbyNeural.
- **She speaks first**: a fixed greeting, voiced and lip-synced once and cached (`greeting.py`),
  plays the moment the interview starts; her opening question follows it.
- **Question variety**: a journalist's range of angles, one suggested per turn (`anchor.ANGLES`).
- **Cloud lip-sync**: the class `Lipsync` on a Modal **L40S** (1.1x real time once warm, ~46 s
  cold start with everything cached). It has no public URL; only token holders' page loads wake it.

## How to run it

Locally (workstation GPU):

```sh
uv run python scripts/anchor_assets.py            # once: the anchor's media, from the newsroom
cd ~/musetalk-local/MuseTalk && ~/musetalk-local/venv/bin/python \
  "../../Documents/d-drive/New Projects/iomarkets-live-studio/lipsync/server.py"   # :8766
uv run studio serve                                # http://127.0.0.1:8000
```

Deployed (Modal): `uv run --no-project --with modal==1.6.1 modal deploy deploy/modal_app.py`.
The private link with its token is in `~/.config/iomarkets-studio/judges-link.txt` (mode 600):
open it with `xdg-open "$(cat ~/.config/iomarkets-studio/judges-link.txt)"`, never paste it.
`bash deploy/warm.sh on 2` keeps the GPU up for two hours, then it switches itself off.
Costs and every guard against surprise bills: `docs/DEPLOY.md`.

## Open problems (start here tomorrow)

0. **Requested 2026-10-30: testers use their own API keys**, so their sessions do not run up the
   operator's bills. Design to agree before building:
   - The page gets an optional "Your Meta API key" field (and Fireworks, optional). The key
     goes to the studio server with each request (brief, live socket), is used for that
     session only, held in memory, never logged, stored or put in a URL. Without one, the
     operator's key is used as now, under the daily cap.
   - Meta is most of the per-session cost (~$1.30). The other costs are the operator's whatever
     key is used: the Modal GPU (~$0.50 per interview) and CPU. Options for those: lip-sync
     only for the operator's token, or a per-day GPU-minute cap like the Meta one.
   - Fireworks (Muse Spark Open) can stay on the operator's key: it edits briefs, cents.
   - Check the Meta API terms allow a third party's key to be used through the studio.
1. **The anchor's replies are slow on the deployed link.** Each sentence is voiced, lip-synced
   on the GPU, returned and downloaded before it plays, so she starts ~5-7 s after the guest
   stops (estimate; not yet measured per step). Every sentence now logs a line
   `[speak] line N part M: voiced at …, lip-sync …, out at …` (Modal: `modal app logs
   iomarkets-live-studio`): run one interview and read them first. Then, in order of
   payoff for effort:
   - **Cached acknowledgements**: five or six short reactions ("Right.", "I see. …"), voiced and
     lip-synced once like the greeting, played the instant the guest stops while the real
     reply renders. Hides most of the wait; reuses `greeting.py`.
   - **Shorter first chunks**: split every reply's first sentence at a comma or after ~6 words
     (`live._short_start`), so the first clip renders in ~2 s.
   - **Streaming the clip** as it renders (fragmented MP4 or WebRTC) instead of waiting for
     the whole sentence: biggest gain, biggest change.
2. **The guest's camera did not show in their box** on the deployed link (the answers still
   recorded). Fixed in the page (the camera video now sits full size under the canvas and is
   started and restarted explicitly) but **not yet confirmed** by the operator.
